## P0：不处理不可宣称完成
| 风险 | 错误做法 | 必须处理 |
|---|---|---|
| 官方插件权限未知 | 虚构工具调用结果 | 授权后能力探测，记录版本/工具/证据 |
| 品牌与格式混淆 | 把 CapCut 工程叫剪映草稿 | 目标程序实际打开和修改、独立验收 |
| 计划代替执行 | 输出 plan.json 即宣称剪好 | 真实编辑、文件存在、播放及工程验证 |
| 质量被蒙混 | 静态模拟当成端到端 | 模拟/真实测试分报告且通过真机E2E |
| 用户失去控制 | AI无提示覆盖用户风格/工程 | 固定风格优先级，版本化与审批门禁 |
| 来源不可信 | 自动运行新发现 repo | 只读调研，用户批准并审查后执行 |

## P1：开发时必须处理
- 素材内容理解需要图像、音频或字幕证据，不准凭标题编故事。
- 插件无法二次修改时准确退化：停止并明确说明，不以重新导出视频等同“修改工程”。
- 素材时间基准和目标时间基准转换，帧/微秒整数验证、字幕区间不越界。
- 字体、音乐、特效、字幕等功能差异导致的降级必须可见且可选择。
- 第三方引入记录许可证与来源。本项目**明确个人非商用**，不将商用许可证兼容作为本阶段拦截理由，但仍需保留源项目许可条件。
- 本地路径跨 Windows/macOS 差异、中文/空格/Unicode 支持、长路径。
- 自定义 Skill 的 prompt injection 和本地文件/凭据越权，使用沙箱、只读解析和显式用户授权。

## P2：体验与长远治理
- Skill 研究结果做版本快照，避免每次联网与同名歧义。
- 用户优秀成片提取的风格可说明依据，可回滚、禁止覆盖现有同名 Skill。
- 导出后能找回工程/成片/历史；低噪声 UI，别滥发过程通知。
- 非必要不下载第三方大仓库/权重/视频模板。

## 阶段出口
G0 产品规格冻结：文档与路由都已清楚，仍不代表软件实现。
G1 官方能力验证：真实工具清单、成功的“建项目/改时间线/读状态/导出”证据。
G2 本地端到端：用户素材从一句话到 MP4 和已支持的可编辑工程。
G3 质量/异常/回滚：版本管理、风格切换、断点恢复、QA、Skill 沉淀。
G4 开发完成：全部验收项有真机记录，实际不支持的功能有明确状态而非伪成功。

## 审计最终判定
架构方向可执行，风险集中在 **CapCut 插件权限与工程读取/导出能力**。它是必须最先探明的技术关口。不得把 C 方案改成“主路径”来掩盖官方接口不可用；如确实缺能力，需明确用户可选的兼容适配，并记录实现路线。
