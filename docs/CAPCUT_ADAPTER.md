# CapCut 官方接入与剪映兼容协议

## 0. 唯一主执行器
官方入口：https://www.capcut.com/tools/capcut-x-codex
由用户在授权的桌面 Codex 环境，按官方实时安装指引完成连接。开发代理只在授权连接后进行实际工具发现和功能探测。

严禁根据宣传页猜工具名称/参数，严禁使用本开发包假想接口去调用真实服务。

## 1. 能力矩阵（启动时动态检测；未知=unknown）
| 能力 | 判定条件 |
|---|---|
| 授权/连接 | 当前会话可调用官方插件并成功完成只读校验 |
| 项目创建 | 真实新工程/草稿可被编辑器识别 |
| 素材导入 | 实际项目引用与素材一一对应 |
| 镜头裁剪/重排 | 读取回来的片段时间、顺序与计划相符 |
| 字幕创建与修改 | 可读回字幕内容与时间范围，或用户在编辑器确认 |
| 音频添加与音量 | 确认轨道、音量及实际成片 |
| 局部二次修改 | 不删除既有工程，可在当前工程上精确修改 |
| CapCut 工程交付 | 用户能重新打开并修改的真实工程或官方编辑链接 |
| MP4 导出 | 文件存在且能播放、分辨率/时长/音轨符合计划 |
| 剪映国内草稿 | 在目标剪映专业版版本实际打开、修改并保存 |

每一项记录 supported / unsupported / unknown / blocked，附工具响应、版本与时间，不凭 README 推断。

## 2. Adapter 的逻辑合同
- discover_capabilities() → 带证据的能力矩阵；
- create_or_open_project(project, assets) → 可追溯真实工程标识；
- apply_plan(project, plan) → 每操作结果、实际时间线信息或可复核链接；
- revise(project, patch, expected_revision) → 新版本而非覆盖旧成品；
- export(project, requested_formats) → 实际路径/链接、元数据和逐项状态；
- verify(project, artifacts) → 外部读回、媒体探测、用户可操作性与QA报告。

以上仅为项目内**逻辑接口**；具体实现要在实测官方插件后映射，不能直接把这些名称当成官方工具。对不支持的能力必须返回结构化错误。

## 3. 官方端流程
授权 → 只读探测 → 测试素材小工程 → 时间线裁切/排序 → 保存快照 → 修改一个片段 → 导出视频 → 尝试工程重开/可编辑验证。
必须先完成上述最小实测再承诺批量、自动导出或用户 Skill。

## 4. 格式边界
- “导出视频”：MP4/MOV等可播放文件，可作为输出但**不是**编辑工程。
- “CapCut 可编辑工程”：官方环境实测可再次编辑；可能是云工程/项目标识，不假定本地 .json。
- “剪映草稿”：国内剪映可识别、打开、继续编辑的工程文件/目录，单独实测。不能因为 CapCut 属于同一生态就认为自动兼容。

## 5. C参考方案的接入原则
参考 https://github.com/Mal-Suen/JianYing-AutoEdit-MCP 和 https://github.com/GuanYixuan/pyJianYingDraft 的镜头 JSON、整数微秒时间线、字幕轨与输出校验。

若用户明确请求国内剪映草稿且官方不支持：
1. 明确告知当前官方路径不支持。
2. 用户可选择启用 **标记为兼容模式** 的 C 草稿适配器，先验证目标剪映版本；不要自动启用。
3. 草稿保存需保留素材来源/路径，建立新的独立工程，回读并重开验证。
4. 如果无法验证，则返回“不支持/未验证”，可以交付已验证的 MP4 或 CapCut 工程，不可伪造成功。

## 6. 失败处理
E_AUTH 未授权；E_TOOL 不支持；E_MEDIA 素材问题；E_PLAN 计划越界；E_APPLY 写入失败；E_EXPORT 导出失败；E_DRAFT_COMPAT 工程不兼容；E_QA 验收失败。
所有失败：保留上一个有效工程版本 + 返回清晰恢复建议 + 不隐式执行另一套后端。

## 7. 安全与事实性
本地视频可能具有隐私和版权约束。除用户明确授权，不调用云存储、付费模型、第三方素材抓取或未知脚本。CapCut 插件自身的外部传输说明需以实际授权界面为准。
