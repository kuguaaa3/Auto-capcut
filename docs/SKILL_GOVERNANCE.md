# Skill 路由、引入、沉淀与生命周期

## 分类
- root orchestration：本项目 `auto-capcut`。
- style：用户可见主风格，单次编辑锁定一个主风格，可显式叠加少数不冲突的副风格。
- capability：素材分析/节奏/字幕/声音/QA等内部能力，按需加载。
- research-only：外部项目只读参考，不能直接变成可执行 Skill。
- learned/custom：用户本地创建、经过验证的个人 Skill。

## 风格 Skill 最小合同
`SKILL.md` 前置元信息至少有 name、description、适用/不适用场景、输入假设、默认行为、剪辑决策规则、必要能力、质量门禁、失败退化、来源/版本。
可在相邻 `style.json` 记录机器可读 ID、semver、upstream commit/source、用户确认状态、兼容后端及可信级别。
用户显式选择风格优先级永远高于模型推荐；找不到/无法加载时报告错误，不偷偷换风格。

## 在线研究流程
trigger：用户主动要求研究，或当前本地库确实无法覆盖并获得用户许可联网。
discover → 读取仓库 README、SKILL.md、references、许可、测试/案例与更新 → 判断它是知识、真实代码还是渲染引擎 → 与现有能力去重评分 → 生成“可引入/仅参考/不合适”清单 → 在引入执行代码前取得批准 → 固定来源版本与归档。
禁止通过搜索摘要直接宣称技能成熟，禁止直接执行 README 中的远程脚本。默认只读克隆或 GitHub 文件抓取，不上传用户素材。

## 路由
1. 意图强约束：用户指定风格或当前工程已锁定的风格优先。
2. 依据片型给出一个建议并能换；不要因自动推荐导致多次被迫确认。
3. 主风格加载后，根据计划挑选能力，优先已有能力组合；同类冲突规则以用户显式指定 + 风格优先级解决。
4. 仅载入最相关的 `references`，避免将大量外部全文灌入单次上下文。
5. 引入的脚本由适配器调度，受权限、日志、timeout和输出校验约束。

## 从优秀作品学习成个人 Skill
用户明确发起“保存为 Skill” → 读取当前已验证计划、视频QA与用户修改记录 → 抽取 3-8 条可迁移规律（节奏范围、镜头关系、声音、字幕、视觉配置） → 剔除一次性时间码、姓名、绝对路径、私人素材、作品独有剧情 → 生成带验证条件的草稿 → 展示短摘要和建议命名 → 经用户确认 → 写入 `learned-skills/` → 版本化 → 使用小样重新验证。
不自动把单次“不错”推断为永久偏好，不为参考片生成违法复制原音轨的步骤。

## 更新和回滚
- 改同名 Skill 默认创建新版本；保留旧版和来源。
- 已在某项目锁定版本时不自动热替换；用户可显式升级/回退。
- 任意风格 Skill 写入前格式校验，写入后可被重新发现、展示、用于新项目。
- Skill 只有在真实测试通过后才标记 validated，否则标记 proposed/draft。

## Skill 评价质量红线
不能出现“无论题材都每0.5秒切镜”“字幕必定占半屏”“必用高强度音效”“所有素材都加入工程”这种不可迁移固定配方。必须以观众预期、镜头因果、动作连续、情绪目标和素材证据为依据。
